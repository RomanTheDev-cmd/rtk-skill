# RTK: условное сокращение вывода

Единый источник Codex/Claude — эта папка iCloud; CLI установлен локально `/opt/homebrew/bin/rtk` (проверена версия 1.0.1). Это ограниченное внедрение двух фильтров, не обещание проверки всех команд RTK. Штатные служебные данные RTK на macOS находятся локально в `~/Library/Application Support/rtk`. Если потребуется отдельное Python-окружение — `~/.local/share/rtk`, отдельный кэш — `~/.cache/rtk`; бинарники и окружения в iCloud не помещать.

## Когда применять

Только для предварительного обзора большого сохранённого лога, когда детали сейчас не нужны. Порог помощника — 4096 байт; это техническое умолчание, не доказательство полезности. Основной метод и критерий качества выбираются по задаче. RTK не требуется для каждой команды, коротких результатов или ответа пользователю.

Для точных инструкций/цитат, расследования ошибки, проверки доказательств, исходного кода, геометрии и окончательного утверждения PASS читать первичный материал нужным объёмом. При сомнении вернуться к нему. Сжатая сводка не заменяет результат проверки и не доказывает смысловую правильность.

## Сохранить оригинал один раз

1. Проверить полномочия и побочные эффекты исходной команды. Запустить её один раз обычным разрешённым инструментом; сохранить полный stdout/stderr, команду, рабочую папку, фактический код выхода и значимые входы в проекте. Раздельные потоки можно сохранить раздельно; для сводки подготовить общий лог, не теряя первичных потоков.
2. При ненулевом/неизвестном исходном коде, ошибке, пропущенных тестах или необходимости подробностей — разбирать оригинал. Не повторять исходную команду ради RTK. Переданный помощнику код должен быть фактическим, не выдуманным; помощник не умеет доказать его происхождение.
3. Только если нужен обзор большого успешного результата — выполнить помощник на сохранённом файле:

```sh
python3 '<общий источник>/scripts/compact_log.py' --input '<проект>/original.log' --source-exit-code 0 --kind pytest --purpose overview --out '<проект>/новая-папка-сводки'
```

`--kind git-log` применим только к оригиналу, созданному разрешённой обзорной командой `git log --format='%h %s (%ar) <%an>%n%b%n---END---'`. Обычный немаркированный git log помощник оставляет целиком. Для сводки не менять/повторять уже выполненную команду. Подробности тел коммитов читать из оригинала; сводка годится лишь для списка.

## Защита качества

- `summary.log` и `result.json` создаются в новом каталоге вне навыка; существующий каталог не перезаписывается. Оригинал не изменяется. Прерывание без полного читаемого result.json — незавершённая операция, а не успешный результат; выбрать новое имя и сохранить частичные материалы.
- Помощник запускает только `rtk pipe`, не исходную команду. Сохраняет исходный код отдельно от кода фильтра; обычный исходный код 0–255 возвращает наружу; для сигнала/кода вне этого диапазона помощник завершается с 1, сохраняя точное исходное число в метаданных. При ошибке фильтра, несовпадении счётчиков pytest/коммитов, неизвестном формате, малом логе или отсутствии сокращения сводка содержит полный оригинал с причиной. Файл >10 MiB не обрабатывается CLI: читать оригинал напрямую.
- `compacted=true` означает лишь полученную меньшую обзорную сводку с проверенными ограниченными признаками. Это не функциональный PASS и не доказательство сохранения каждой значимой детали. Проверка кодов/счётчиков не заменяет чтение по задаче.
- Известная особенность прямого `rtk pipe`: код 0 не равен успеху исходного процесса; pytest-фильтр может скрыть ImportError, git-log требует маркеры. Поэтому для этих маршрутов использовать помощник с отдельным исходным кодом и сохранять первичный лог.
- Помощник отключает telemetry и recall для вызова; `rtk init`, глобальные хуки, proxy, автоматический перехват всех команд и чтение истории чатов не входят в это внедрение. Не включать их просто ради сокращения токенов.
- `rtk gain`/bytes÷4 — локальные приблизительные метрики отдельных команд. Внедрённый pipe не регистрирует все сводки в gain. Ни одна из этих величин не доказывает снижение общего счёта; для сравнения нужны фактические usage и качество на одинаковых задачах.

## Подключение и границы

Читать необходимые systematic-debugging/TDD по их условиям. Не создавать второй источник правил аудита или CAD. Modeling не менять без применимого конкретного разрешения; запуск 3D-печати категорически запрещён, в том числе через RTK и агентов. Ограничения нарезки/рендера/публикации сохраняются.

Версия и изменения — VERSION/CHANGELOG.md. Перед правкой — полная копия по общим правилам. Установочные тесты/охват и первичные логи — во внешнем проекте «Аудит правил», runs/2026-10-19-install-debug-tdd-rtk. Полная матрица не заменяется количеством тестов. Неизвестное и неиспытанные маршруты назвать прямо.
